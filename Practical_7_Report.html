1. Practical Objective & Overview
Objective: To implement JWT-based authentication, cryptographic password hashing with bcrypt, and server-side request input validation as part of the Express middleware pipeline protecting backend routes.

In Practical 7, user authentication and input validation are integrated into the full-stack Task Management application. Passwords are securely hashed before persisting to MongoDB using a Mongoose pre-save hook. Upon successful authentication, JSON Web Tokens (JWT) signed with a secure secret are issued with a 1-hour expiration. An Express authentication middleware intercepts incoming requests to protected task routes, verifies the cryptographic signature of the Bearer token, decodes the payload, and attaches the authenticated user document to req.user. Additionally, server-side validation middleware sanitizes incoming payloads and rejects malformed inputs prior to database execution.

3. Key Questions & Technical Analysis
Q1: Why must passwords be hashed before storage instead of saved as plain text, even in a lab/demo project?
Storing plaintext passwords is a catastrophic security failure. Passwords must be hashed using a slow, salted cryptographic algorithm (such as bcrypt) for the following reasons:
  • Breach Protection: If a database dump, backup, or unauthorized developer inspects the storage layer, hashed passwords cannot be trivially reversed.
  • Protection Against Credential Stuffing: Because users frequently reuse passwords across multiple services (email, banking, university portals), leaking plaintext passwords compromises the user's entire digital footprint.
  • Salting Prevents Rainbow Table Attacks: bcrypt automatically generates a unique cryptographic salt for each password, ensuring that identical passwords result in completely different hashes, neutralizing precomputed lookup table attacks.
  • Adaptive Work Factor: bcrypt allows adjusting the cost factor (salt rounds), deliberately slowing down brute-force attacks on high-performance GPUs.
Q2: What does the authentication middleware actually verify, and what happens if the token is missing or expired?
The protect authentication middleware performs four critical sequential checks on incoming HTTP requests:
  1. Header Format Verification: Checks that the Authorization request header is present and formatted according to the HTTP standard: Bearer <token>. If omitted, it immediately halts the request with 401 Unauthorized ("No token provided").
  2. Cryptographic Signature Verification: Using jwt.verify(token, secret), it validates the HMAC-SHA256 signature against the server's private JWT_SECRET. If the token payload has been tampered with or altered by the client, it throws a JsonWebTokenError and returns 401 Unauthorized.
  3. Expiration Check (exp claim): The middleware checks the expiration timestamp. If the token's lifetime (e.g., 1 hour) has lapsed, it throws TokenExpiredError, returning a 401 Unauthorized response instructing the client to re-authenticate.
  4. Database User Verification: Extracts decoded.id and queries MongoDB to confirm the user account still exists in the system before populating req.user and invoking next().
Q3: Why should input validation happen on the server even if the frontend already validates the same fields?
Frontend validation exists strictly for User Experience (UX) to provide immediate visual feedback. It provides zero real security.
  • Bypassability: Any client can completely circumvent frontend validation by sending raw HTTP requests using tools like cURL, Thunder Client, Postman, or automated Python scripts.
  • Server as Source of Truth: The server-side validation middleware represents the authoritative barrier that guards data integrity. It prevents NoSQL injection, malformed documents, oversized payloads, and undefined field errors before queries reach the database.
  • Defense in Depth: Validating inputs at both the middleware level (Express) and schema level (Mongoose) ensures strict fail-safe enforcement across all entry points.
4. Supplementary Problems Solutions
1. /me Endpoint (GET /auth/me):
A protected endpoint was implemented that extracts the authenticated user profile from req.user (decoded from the incoming JWT by protect middleware) and returns their name, email, role, and creation timestamp without exposing sensitive fields.

An interactive "Logout" button was added to the Task Dashboard and Navigation Bar. Triggering logout removes the stored JWT token and user metadata from localStorage, resets the React application state, and locks access to protected task routes.
5. Code Implementation Highlights

A) User Model with bcrypt Hashing Pre-Save Hook (backend/models/User.js):

// Hash password with bcrypt before saving to MongoDB
userSchema.pre('save', async function () {
  if (!this.isModified('password')) return;
  const salt = await bcrypt.genSalt(10);
  this.password = await bcrypt.hash(this.password, salt);
});

// Compare password during login
userSchema.methods.matchPassword = async function (enteredPassword) {
  return await bcrypt.compare(enteredPassword, this.password);
};

B) JWT Verification & Route Protection Middleware (backend/middleware/auth.js):

export const protect = async (req, res, next) => {
  let token;
  if (req.headers.authorization && req.headers.authorization.startsWith('Bearer')) {
    token = req.headers.authorization.split(' ')[1];
  }
  if (!token) {
    return res.status(401).json({ success: false, error: 'Access denied. No token provided.' });
  }
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = await User.findById(decoded.id).select('-password');
    next();
  } catch (error) {
    return res.status(401).json({ success: false, error: 'Invalid or expired token.' });
  }
};

C) Server-Side Input Validation Middleware (backend/middleware/validation.js):

export const validateTaskInput = (req, res, next) => {
  const { title } = req.body;
  if (req.method === 'POST' && (!title || title.trim().length === 0)) {
    return res.status(400).json({
      success: false,
      error: 'Validation Error',
      details: ["Task 'title' is required and cannot be empty"]
    });
  }
  next();
};
