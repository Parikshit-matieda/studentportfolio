3. Performance using lazy loading and code splitting techniques:

Architecture / Chunk Loading Flow: Before (single monolithic bundle): main.bundle.js ──────────────────► [Home][Projects][Tasks][Contact] all loaded upfront After (route-based code splitting): main.bundle.js ────────► loads on first visit (Header, Footer, Router) Home.chunk.js ─────────► loaded only when / is visited Projects.chunk.js ─────► loaded only when /projects is visited Tasks.chunk.js ────────► loaded only when /tasks is visited Contact.chunk.js ──────► loaded only when /contact is visited TaskAnalytics.chunk.js ─► heavy Chart.js library loaded on-demand

Code Implementation (src/App.jsx & src/utils/lazyWithDelay.js):

import { Suspense } from 'react'; import { lazyWithDelay } from './utils/lazyWithDelay'; import PageLoader from './components/PageLoader'; // Dynamic lazy route imports with 300ms anti-flicker threshold const Home = lazyWithDelay(() => import('./components/Home'), 300); const Projects = lazyWithDelay(() => import('./components/Projects'), 300); const Tasks = lazyWithDelay(() => import('./components/Tasks'), 300); const Contact = lazyWithDelay(() => import('./components/Contact'), 300); function App() { return ( <HashRouter> <ScrollProgressBar /> <Header /> <main className="main-content"> <Suspense fallback={<PageLoader message="Loading requested view..." />}> <Routes> <Route path="/" element={<Home />} /> <Route path="/projects" element={<Projects />} /> <Route path="/tasks" element={<Tasks />} /> <Route path="/contact" element={<Contact />} /> </Routes> </Suspense> </main> <Footer /> </HashRouter> ); }

4. Key Questions & Technical Analysis:

Q1: What is the difference between the initial bundle and a lazy-loaded chunk in terms of when each is downloaded?

The initial bundle (e.g. index-RK4o_U2Q.js) is referenced directly in the HTML entry point (<script type="module" src="...">) and is downloaded immediately during initial page request. A lazy-loaded chunk (e.g. Projects--JNtvOJi.js or TaskAnalyticsChart-B_FY-rBM.js) is generated through dynamic import() statements; the browser only initiates an HTTP request for this chunk when the user triggers the corresponding route navigation or interacts with an on-demand UI element.

Q2: Why does lazy loading improve perceived performance even though the total amount of code downloaded eventually stays the same?

Perceived performance depends heavily on First Contentful Paint (FCP) and Time to Interactive (TTI). By deferring non-critical routes and heavy libraries (such as Chart.js), the browser has to download, parse, compile, and execute substantially fewer bytes on initial load. The main thread unblocks hundreds of milliseconds earlier, rendering visible content faster. Even though visiting every route eventually downloads the same aggregate bytes, spreading those downloads across the user journey eliminates upfront lag.

Q3: In what situations would lazy loading not be worth the added complexity?

Lazy loading introduces slight architectural overhead (managing Suspense boundaries, network latency pauses between route transitions, and extra network handshakes). It is not recommended for: (1) Very small single-page applications where the entire bundle is under 100 kB; (2) Critical landing page components required above-the-fold; (3) Environments requiring offline-first PWA caching where all assets must be available offline upfront.

5. Supplementary Problems Solved:

  • Heavy Third-Party Component Lazy Loading: Chart.js and react-chartjs-2 are wrapped in TaskAnalyticsChart.jsx and loaded via React.lazy() only when the user toggles the analytics tab, saving 173.50 kB from the initial load.
  • Minimum-Delay Fallback: Created lazyWithDelay.js with a 300ms minimum threshold using Promise.all([import(), timeout]), eliminating jarring spinner flickers on high-speed broadband.
  • Profiler Optimization: Isolated scroll tracking state into ScrollProgressBar.jsx to prevent the root <App /> component from re-rendering at 60fps during window scroll, and memoized TaskCard with React.memo to prevent task grid re-renders while typing.
